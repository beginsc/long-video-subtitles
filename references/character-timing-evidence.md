# 字符级拆分的时间来源与构轴依据

当显示条目的起止由原始字符对齐、字符跨度或剔除标点后的字符边界计算时使用，包括继承旧项目的分段，以及在该边界上继续延长/限制显示时间。仅出现 parent_ids 或文字换行不代表字符级拆分；普通词级切分和没有这类来源的固定轴 SRT 不要求补造字符数据。

## 默认工单输入

产生分段的原文整理员或制作员，随候选提交时间证据包及只含相关原文的对齐/规则摘录。主代理验收后将其冻结为项目侧文件，例如 `evidence/timing/timing-evidence.vNN.json`。复用旧项目时先从已存对齐和构轴记录整理，无需为整理来源重跑 ASR。

凡工单核心或只读邻条包含这些分段，主代理在派单前写入 `timing_evidence`，列 `cue_ids`、`packet_path`、`packet_sha256`；包和需实际读取的摘录都以绝对路径、SHA-256、用途列入 `inputs`。从翻译开始，后续校对、编辑、制作、质检等相关工单均默认附带，不能只在某位员工的聊天或 handoff 中提及。正在生成分段的上游工单把该包列为交付物；当前尚无分段时不虚构已存在的包。

这是调度侧协议。`chunks/apply`、`semantic_windows.py` 不会自动收集或验证此包；主代理负责打包、核对与传递，员工负责实际读取。不要向已签名批次或阶段响应强塞新字段。

## 包内最小内容

可用一份 JSON 索引多份摘录。每个适用 cue 一条记录，共享文件只需引用一次；只带本批核心和只读上下文所需证据，不重复塞入整片 ASR。记录以下内容：

| 内容 | 必须能回答的问题 |
| --- | --- |
| 来源与版本 | 对应哪份媒体、原始对齐文件和生成工具/配置？保存路径、实际 SHA-256、可取得的工具版本；注明原始段索引、块/说话人及摘录定位。原始文件过大时交付可核对的只读摘录，并保留其源文件摘要。 |
| 当前条目绑定 | `cue_id`、`parent_ids`、当前 `source`、`start_ms/end_ms`，以及生成证据时的正式源版本路径/摘要；指出原始文本跨度与当前源文的映射。重复短语须靠索引区分，不能仅凭文字搜索取第一次命中。 |
| 时间坐标 | 原对齐单位、块起点偏移 `offset_ms`、换算到整片毫秒的公式及实际舍入方式；原数据已为绝对时间时注明，偏移只加一次。 |
| 边界原始记录 | 产生起点和终点的字符索引、字符值及原始起止时间，连同相邻字符和所属词记录。跨度注明零/一基及开闭区间；若做过文本归一化，附索引映射。保留相关标点、空白、未对齐项及原词尾，不能只给筛选后的数字。 |
| 构轴规则 | 实际采用的首尾字符选择/标点处理规则、脚本或配置版本摘要，以及可直接读的最小代码摘录或等价公式。说明对齐边界如何变成显示起止，列出本条实际用到的延长量、最短时长、下一条/停顿/场景边界限制及其来源；无调整也明确写出。 |
| 计算与差异 | 用实际输入数值复算 `start_ms/end_ms`，结果应等于当前 cue。区分字符边界、包含标点的词尾和最终显示边界；有差异逐项解释，不能只写“沿用旧轴”。 |
| 证据状态与范围 | 按条记录 `complete` 或 `unavailable`、缺项与原因、生成者及实际复核者。complete 仅指来源/计算材料齐备；另记是否实际听过音频及其范围，数据复算不等于听校。 |

构轴脚本若夹带旧译文，只提供带来源摘要和定位的相关计算代码摘录；员工不必读取整份旧脚本。对齐摘录同样只保留所需原文、索引、时间和证据，避免把历史译稿或评测参考带进新翻译。

例如，某项目的末字母结束于 13.716 秒，带句号的词尾为 14.737 秒，规则在末字母后延长 180 毫秒，并受最短显示时长与下一条开始限制。应同时保存三种边界及该条计算：`min(max(13716 + 180, 11455 + 800), 14777) = 13896`。这是特定项目的数值示例；新任务记录自己实际采用的规则与参数，不据此统一延长 180 毫秒，也不把 13.896 秒声称为已听证实的发声结束。

## 派单验收与版本传递

主代理派单前核对包/摘录摘要、涉及 ID 和当前条目绑定，并复算边界；员工读取后在 `handoff.inputs` 记录实际包及摘要，在审校说明中引用对应记录及结论。编辑和质检工单须同时带原证据，不能只收到“校对已确认”的文字转述。

证据包绑定生成时的源版本，并逐条绑定源文、parent_ids、显示起止和原始对齐依据。后续仅新增 draft、校对意见或 target 时，全文件摘要会变化：核对上述绑定内容未变即可沿用同一包，无需复制证据或伪造新摘要。条目 ID/文本/时间/映射、对齐依据或构轴规则变化时，另存证据包、重建涉及这些核心或只读邻条的工单，并按岗位交接协议重走受影响审校；制作阶段的新拆分也适用。

已发工单漏附件时，不改写冻结工单。主代理把补充文件及摘要另记到该任务的 `supplemental_inputs`，员工实际读取后写入 handoff；后续新工单把补充证据纳入正式 `inputs/timing_evidence`。仅补足解释且未改源文、时间或既有结论时，不因附件新增就重跑翻译；若证据推翻既有判断或引出源文疑点，按 source_checks 和现有失效规则处理。

缺关键对齐/规则、无法复算或摘要不符时，先由主代理退回原文整理/制作岗位查已存原件，避免让每个下游重复追问；不按当前时间倒推出“原始规则”。确实无法恢复则记录 unavailable 和受影响 ID，仍可继续不依赖该证据的已授权工作。相关时间判断保持待证据；需据此审定的校对为 UNCLEAR、编辑为 needs_review，不能以机器 QA 通过或文件存在替代核验。无法解释的源文/时轴疑点按 review-evidence.md 纳入正式 source_checks。
