# 人物证据与信息保留

只在实际出现近名、同名或角色混淆时使用；不为所有代词新增工单。沿用源稿、译者、独立审校三岗位和同一个 issues 队列。原始 ASR、source_word_ranges 与词时间保留，不根据目标译名回写原始词，不做全局近音替换。

## 先界定未知范围

把“这个音写作哪个名字”“这里指谁”“谁对谁做了什么”分开。一个姓名写错，不自动使其余动作、对象或亲属关系都未知；知道角色的名字，也不自动知道残缺句的谓语或施受方向。源岗只为争议组列出实际有用的槽位，例如提及人物、行动者、病者、作者、受赠者；分别保存稳定事实与未决部分。

优先看完整源话及连续邻接，再按具体疑点取证。明确命名后的连续同一人物叙述、显式关系称呼、源话自身的更正或区分，可以支持指称解析；仅仅“整段都在谈某人”不够。把候选人物逐个代入，核对源话里的动作、关系、叙述切换和相反证据，不能凭声似、出现频率或熟悉剧情选人。

实际看过的画面可支撑指称：须说明哪里把当前话语与该人物/动作关联起来。人物恰好出现在画面上、蒙太奇相邻、官网描述其一般性格，都不能单独证明当前说的是此人。外部资料可核实名称、亲属或作品署名；不能把“剧情里确实如此”当作“讲者必定这样说”。外部资料、词表和第二套ASR只作补充，仍需当前源话或有明确指称关联的音画锚点。存在源话与画面冲突时保留冲突，不纠正成自己熟悉的剧情。

## 选择最少损失的表达

- 指称已经由实际证据稳定限定：用已核实名字或原话层级的称呼，并保留原话称呼承担的关系信息；“他的父亲”不能只换成姓名而丢掉父子关系。可以解决影响目标译文的指称问题，记录 `referent_only`；原声音形未听辨则保持 `source_form_confirmed:false`，不能写“已听到名字”。
- 姓名未定，但关系或事件角色已知：用源话支持的关系称呼/角色称呼，维持同一人的连续指代。只有原话支持“姐姐”“送礼者”等关系时才可这样称呼，不能凭领域常识新加亲属或作者关系。
- 仅部分关系未定：保住其余已知信息，未知槽位可局部省名或保留原有代词。不要把整个关系退成“另一对角色／其中一人／对方”，也不能为了增加具体性把未知槽位强配给某人。
- 有用的安全部分仍存在：`safe_partial`，保持 provisional、草稿。关键动作、对象、肯否或关系方向缺失且没有可支持表达：`hold`；人名证据不能解除未知谓语/极性的约束。

“保住信息”不是必须把每个代词换成人名。普通正确表达沿用，不增加重复姓名或解释字幕。新增名字、关系称呼或恢复被省略的身份后，只复查完整的相关语义组；必要时加项目词组保护并重做实际折行/显示检查，不改全片时长参数。

## 在原有问题中记录

为实质身份修订在 `disposition.entity_evidence` 内记录：

```json
{
  "resolution_scope": "referent_only",
  "evidence": [
    {"id":"e1", "kind":"source_context", "locator":"原始文件、单位及相邻范围", "observation":"实际原话或观察能支持什么"}
  ],
  "claims": [
    {"slot":"actor", "state":"supported", "value":"已支持的指称", "evidence_ids":["e1"], "source_form_confirmed":false},
    {"slot":"recipient", "state":"unknown", "value":"", "evidence_ids":[], "source_form_confirmed":false}
  ],
  "preserved_facts": ["原话已确认并应保留的动作或关系"],
  "conflicts": [],
  "limitations": "原声词形未听辨；仅支持声明的指称范围"
}
```

证据 kind 可用 `source_context`、`visual_reference`、`audio_observation`、`author_transcript`；补充证据为 `external_fact`、`name_glossary`、`asr_hypothesis`。每个 supported 槽位须有可定位的当前源话/音画锚点，不能只有补充资料。`source_form_confirmed:true` 必须另有 `lexical_evidence_ids` 指向实际听辨或可信作者逐字稿；不是只要证据里出现 audio 字样就已听辨。若 `resolution_scope:source_word`，至少在一个实际修订词形的 claim 写 `repairs_source_word:true`，这些槽位须满足词形确认条件；同一问题其他仅靠上下文支持的槽位不必谎称听辨。参考层原词仍不覆盖，修正另存。

claims 只列本疑点要解决的槽位；不要为整个句子机械填表。未知槽位或未消除的冲突仍阻止 `verified_repair/resolved`。证据收敛、实质指称问题已解决并经独立审校时，可 `verified_repair/resolved`，同时明确 referent_only 不等于声学确认；不能保留未知槽位却把整条问题标 resolved。

`conflicts` 记录仍影响所声明指称/角色的竞争证据；原始 ASR 词形不同与“原声未听辨”照实保留在 evidence/limitations，不能删去。如果连续语义已确定指称，单纯未确认音形不必伪装成同样强的另一指称；但若原话可能确实换人、人物自身纠正或相反关系仍有实质可能，就保留 conflicts 和 provisional，不借 referent_only 标签清除争议。

若同一问题还含未知谓语、极性或因果，在 `source_constraint.unresolved_dimensions` 列出当前未决维度（如 `["entity","polarity"]`），不要只用 risk=referent 掩盖另一个疑点。任一声明的未知 polarity 仍禁止 safe_partial，非空 unresolved_dimensions 阻止整项 verified_repair；解决后只删除实际已解决的维度。关键证据观察和位置写入记录，不用“角色表已确认”或前一版猜译循环自证。

审校先独立看原话、定位证据和实际保存译文，再读上游解释。核对是否把近名当同一人、是否把同一个人拆成多人、病者/作者/受赠者等角色是否被互换，以及是否丢掉本来可支持的具体信息。只改证据能支持的槽位；保持不明极性和残缺谓语约束。审校真实身份、证据、claims 和目标译文均绑定已有 reviewed_sha256；字段变化须局部复查。脚本只能验证结构、引用与绑定，不能判定看过/听过或推理正确。
