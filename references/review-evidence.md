# 疑点证据与审定

本协议针对“报告承认有疑点、数据却写 reviewed”的实测漏洞，不要求普通清晰句都做人工听校。

新项目设置 `meta.quality_contract: evidence-v2`，每条源文检查后写 `source_checks` 列表；确无疑点时为空。检查低置信度词、异常重复/断句、数字/否定、未收录专名、游戏实体混淆和上下文逻辑冲突。置信度仅用来排序，不以单一分数自动改写原文。不能用批量填空列表代替实际阅读。

```json
{"source_checks":[{"id":"a1","kind":"asr","status":"open",
 "reason":"此处宾语异常重复，不能确定原声是重复、口误还是识别错误"}]}
```

kind 为 asr/visual/entity/meaning，ID 在本条内唯一。保存新源版本后重建批次；检查记录进入校对输入摘要，不能靠清空最终 issues 绕过开放疑点。新发现疑点时先加入源版本，再重建受影响批次；源文或证据改变还须按原有术语协议重新发现和绑定。

疑点理由定位到具体短语及已知时间区间，并说明哪些后续指代依赖它。拆句后不把同一宽泛问题算成多个独立错误；汇总同时保留受影响cue列表与原始问题来源。只在证据支持时缩小影响范围，不为降低待审数自动清除子条的疑点。反过来，前条实体未定、后条“它”依赖该实体时，后条也不能凭语法流畅标为确认。

区分转写疑点与背景核查：讲者明确说出的历史排名、意见或版本评价，可以忠实转述并在上下文记忆另记背景未核；不能因没查到资料就一律判为ASR错误。原声词形、主体或逻辑本身不确定时仍用source_checks阻止审定。已冻结旧记录不追溯清空，修正分类须有理由和新版本。

实体关键判断不能只看缩略联系表：检查原尺寸画面、同一对象的连续时刻和可读的单位/建筑标识。选中面板不一定属于正在讨论的对象。阴影、进度条或特效与文本矛盾时先保留候选；画面只能证明可见状态，不能证明讲者说了哪个词。渲染阶段发现新矛盾要返回源文/编辑并重导出，不能让观察摘要与交付字幕各自保留冲突结论。观察记录出错也需勘误，引用具体帧及保存文本。

```text
python <skill>/scripts/subtitle_workbench.py triage source.context.vNN.json review-queue.v01.json
```

triage 汇总 source_checks、UNCLEAR 建议和 issues，带 ID、时间与原文。空队列只说明没有记录待决项，不证明 ASR 正确。针对队列回查短音频、相邻句、准确时间的连续帧或权威资料，优先处理影响否定、数量、行动对象及关键术语的项目。

流畅的近音动作也要看语境：例如 pick up/off、shot/shut、surge/siege 可能改变移动、击落或架起的含义。出现动作冲突时，定位原音并保留可选读法；领域常识只能触发排查，不能直接选定更合理的词。

另查没有源条目承载的空隙。可先用只读工具生成候选窗口：

```text
python <skill>/scripts/evidence_windows.py --source source.context.vNN.json --output evidence-windows.v01.json --min-gap-ms 4000
```

输入须含 `meta.duration_ms`。工具优先合并真实词级时间覆盖，不可用时退回 cue 区间并记录限制；沿用 asr_words_offset_ms 换算媒体时间。结果不是真正独立 VAD，也不是漏听结论。按实际解说节奏调整阈值，短于阈值的遗漏不会自动出现。将这些项目作为媒体窗口队列保存，不能伪造空 cue 消除问题；实际查听后再决定是静音、音乐、哼唱或漏句。确有表达功能的非词语声音按项目风格处理，不能凭参考中的拟声字添加字幕。没有听校能力时记录未核验范围，继续已授权草稿流程。

同一工具另列 `word_duration_candidates`：单词持续超过可调 `--max-word-ms`（默认2000毫秒）时保留cue/parent ID、原词索引和绝对时间，供排查词对齐把停顿或漏句吞进一个词的情况。长叹声也可能真实持续，因此不是自动错误判定，不自动截短、移轴或解除疑点。时间上已有词覆盖也可能漏掉一个实质命题；遇上下文突跳、谓语残缺、数值无承接时仍查整段原声，不能只检查空档列表。

原音切片、能力判断、背景语音归属与模板见 [audio-review.md](audio-review.md)。qa 的 summary 单独统计 error_cues、needs_review_cues 和各检查代码；同一个疑点可触发多个错误，报告区分“疑点条数”和“检查项数”，不能将粗粒度视觉提示计作翻译错误率。

核验后保留原问题，将 status 改 resolved，并记录：

```json
{"resolution":{"method":"audio_review","evidence":["audio-review/cue42.json#listening-note"],
 "note":"实际听取对应片段后的结论及采用/排除另一个读法的理由"}}
```

method 为 audio_review / visual_review / context_review / source_lookup；evidence 必须指向真实可追溯记录或来源，note 说明它为何解决该疑点。字段校验不能证明听过或看过：没有可用音频输入工具时不可声称 audio_review。再次 ASR 可作为辅助证据，不能单凭两个 ASR 一致便填写“已听校”。语境足以消歧时可以 context_review，但不能将猜测包装成证据。

开放 source_checks 会阻止 PASS 和最终导出。校对已标 UNCLEAR 时，编辑要么 needs_review 并列出 issues，要么在真正解决后提供同结构的 `uncertainty_resolution`，方可 reviewed；一条“已核对”的通用说明不够。改变上游 source_checks 会使旧校对失效，应重校；编辑不能偷偷改上游记录。

不确定性未解决仍可 `export --draft` 交付暂定字幕和队列。报告分开说明文本语义复核、ASR 交叉检查、实际听校、视觉抽样和人工确认；同一 GPT 的不同角色不能称独立模型评分。

正式性能结论应使用未见参考的新样本，并由确实可用的独立模型或人工做含原音的语义标注。没有独立评审条件时交付自动指标和明确范围，不阻塞已授权的草稿制作，也不冒充准确率。
