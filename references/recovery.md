# 续做与投入控制

项目状态只有准备、翻译、审校、制作和交付几个业务阶段，各章记录未开始/进行中/完成/等待证据。记录当前文件、执行者和下一步即可。工具校验负责判断文件可读、范围完整；员工的完成消息不是磁盘成果。

恢复时先查是否仍有运行中的员工/进程，再看当前文件和未完成范围。已完成片段直接沿用；不因新会话或员工实例变化重做全片。源媒体或当前文件确有变化时才按实际影响复核。原始 ASR、已完成稿和失败记录保留。

## 限制的是返工，不是正常理解

默认每个片段一次翻译、一次独立审校，具体发现需要时一次局部修复。修复仍不成立就由组长裁决或保留待定，不通过不断更换专家求一个一致答案。工具临时错误可修，但同一失败重复、未知计费结果或配额耗尽时停止自动重试，保存状态。

派工计划写清片段数、岗位、必要依赖和可用并发；每次派工只对应一项实际交付。正常完成的零改字校对是有效结果，无需再验证“为什么没有修改”。若连着出现因版本、日志或交接格式造成的零改字复核，停止这条复核链并修调度，保留既有审校结论。

组长在每次创建/继续员工前检查：这次调用要新增什么成果？是否已有可接受成果？属于原计划还是局部修复？已知预算是否足够？没有具体增量就不派。

## 预算的真实边界

用户给出费用/token/时间上限时，记入 project.json。能够得到宿主级硬限额就启用，并在下一次调用前预留上限内的额度；不能拿累计记账充当事前阻断。并发任务的预留要一起计算，失败尝试不从账上抹去。

原生子 agent 通常不能由本 skill 精确限制其每一个内部模型请求。如果宿主不提供逐请求拦截及实际 usage，本 skill 只能执行派工与返工次数控制，不能承诺硬 token 封顶。严格 token 上限任务应使用具有相应能力的宿主/执行器，或说明当前无法保证后停在可交付的草稿；不得把估计值当精确消耗。

没有数字预算时不强迫用户先设置一个，也不据此无限开展真实实验。遵守上述业务轮次、局部修复和故障停止条件。额外的全片重跑、模型比较、收费二次识别或基准实验不是默认字幕制作步骤。

## 费用未知的外部请求

下载或 ASR 已提交但没有结果时，保留请求标识并查原任务状态。已有响应可重新规范化，不能因为缺最终文件再提交一次计费请求。已有用户授权继续有效；新增数据去向或超出授权范围才需要另行确认。
