# 精简、拆合与改稿的保真复核

在初译整形、编辑改稿或续做旧稿时使用。目标是减少无必要的语义变化；不是禁止自然口语、精简或重新翻译。首次全新翻译仍逐条以原声/源文为依据，不用旧译或参考答案代替理解。

## 决定是否改写

已有准确、自然且符合当前要求的译文可直接保留。校对 PASS 不需要另换一套说法；修改应针对可指出的问题，如语义、术语、语气、阅读速度或断句。用户明确要求全新翻译时执行，但不得把旧版判为天然错误，也不得称旧译对照为独立盲测。

精简前识别本句实际承载的信息：主体/客体、动作、阶段与时间、否定和范围、数量、确定程度、条件/因果，以及有意义的反应/让步。只核对本句出现的项，不为所有句子机械填写空表。检查的是具体源短语与译文对应关系，不是泛写“事实已保留”。

- **阶段不能混同**：计划、正在进行、即将完成、已经完成、仍未完成并不等价；“使行动发生／获得机会”也不等于“行动得手”。结合上下文保住迫近感、持续性与完成状态，不能把观察到的结果退成能力判断，也不能把缺少应对手段写成已经防守失败。army has arrived 先检查是到场、可用还是阵容成型，不因谈到科技就默认最后一种。would、could have 等还可能表达条件或对先前机会的回顾，不直接压成现在的确定判断；保住反事实时，也不要漏掉 could/might 自身的可能性。
- **证据与推断分开**：观察到、预判、可能、知道不应互换。不要把上下文可解释的结果强化为讲者明确断言的意图、诱导或因果。
- **反应也有作用**：预测后的确认、让步后的转折、自我纠正和笑点铺垫可很短，仍须保留其功能。无需逐个保留无信息填充词。
- **评价维度与立场要对应**：速度、消耗进度、资源交换效率和站位不是同一评价。`at a decent pace` 不自动等于“交换很赚”；`set up well` 也未必只指站位，stronger 技能效果不自动收窄为“打得更准”。`I don't mind` 保留讲者个人接受度，不擅自改成“完全没问题”的客观保证。a little / somewhat 等程度不夸大成“多了／完全”；`low` 未说明生命、能量或数量时，先查前后文及可用原音，不凭单位常识补齐属性。反讽可以保留表面夸赞与上下文反差，不直接扩写成讲者未说的训诫。
- **换战线时检查归属**：连续出现两名选手、双方基地或正面与绕后部队时，逐处确认 he/his/they 的主体与客体。必要时重复选手名或阵营帮助读者识别；画面看到某方单位，并不足以证明此刻代词指向该方。证据不够就记录疑点，不凭参考译文裁决。
- **限定的范围要具体**：数字指当前存量、累计损失、本次战损、预期数量还是可施放次数；技能是打向目标、实际命中还是被躲开，分别保留。单张界面只能证明其时刻显示的项目，不能覆盖更早原话。may 不等于“顶多”，seems 不等于“竟然”，not all / not necessarily 的否定范围应与其真正限制的原因或对象对应。`may have ... but ...` 还可能是“虽有……但……”的让步，先读后半句，不机械引入数量不确定。modern day and age 等时代范围不自行缩成某个游戏版本。
- **个人范围与组成要保留**：I usually 是讲者自己的习惯或困难，不泛化为整个种族或所有玩家；always / whenever 的重复频率或条件不能仅剩“又／竟然”。mass 表示大量，不自行增加“纯兵种”的排他性。pretty sure 等置信程度不随意削弱为普通猜测，也不升级为确认。
- **判断依据不能增写**：I think / I believe 通常表达判断，不自行写成“我记得／我印象中”来添加记忆来源。well known for 是名声或常见特点，不自动等于 good at 的能力评价；不愿也不等于不敢。probably not 是倾向于否定，may not / not necessarily 只保留可能性或限制范围，不能都压成“未必”。结合上下文处理，不建立机械逐词替换表。
- **术语放回完整句子检查**：数量、科技等级、动作对象和替换方向由整句决定，词表命中不能证明这些关系正确。基地数量与一本／二本／三本、同时生产数量与生产速度、换掉什么与换成什么分别核对。play/build 等普通词不凭空补成“开局”；只有明确的准备、开局或完成语境才增加该阶段。残句中的单位名可能指使用的部队、受击目标或损失对象，缺少谓语时不要按战术合理性补一个动作。

原文整理时，将原始 ASR、候选修正与采用证据分开。常识或画面显示另一种情况，可能是讲者判断有误、反讽或故意说反；不能仅为战术上合理就改动内外、能否或行为主体。中文残句也要复查：真正的打断可以保留，缺少谓语的识别结果不能因忠于残缺英文自动通过，更不能靠添加省略号隐藏漏词。

否定还要核对其作用对象：`not quite built up` 通常是尚未完全建立，不直接写成尚未开建；`didn't mean to call ...` 否定称呼的意图，不自动否定先前说过的话。`barely does not see` 仍是没有看到，中文“差点没看到”可能反转结果。以完整源句和上下文裁定，不按关键词机械替换。

模式变化与移动、可攻击与已经攻击分开。取消观察模式、解除架起或恢复可移动状态，不自动等于单位已经走动；普通动词的泛化可能丢掉关键操作，即使术语名正确也要复查。数字后省略名词时沿上下文确认指代，并保留约数；两次命中、两只单位各命中一次和两轮齐射不是同一数量关系，不以画面里的单位数补造攻击次数。

未完成的 one / one of his 不能仅因中文需要量词便补“一种／一只”，省略号也不能使猜出的类别成立。go for a building、going down、liftoff 等普通搭配需结合源句、双方归属和当时状态，区分建设／升级／攻击／摧毁、建筑升空／运输机装载；术语名词正确并不能确定动作。用画面判断建筑是在下还是被拆时，跟踪同一对象、地点与准确时刻，不能拿切镜后另一处受攻击的建筑作证。

数值口语化不能制造新的读法：110%可直接保留数字，不缩成容易混淆的“百分之一百一”。等级、数量和属性分别核对；只说 plus three 时不要自动补成3攻3防。常用搭档不自动成为从属的陪练，频繁使用某战术也不等于同时造了大量该建筑；简化中文仍需保留关系和数量类型。

意译比喻时读下一句：若随后围绕“书”等具体物件开玩笑，前句应保留足够的物件铺垫，使观看字幕自身能接住笑点。独立梗解析不能补救正文中消失的触发关系。正式科技名紧接功能解释时，两条若都采用同一个功能俗称会形成空转；在项目语境中区分名称与解释，不从评测参考复制词条。

必要性、选择和克制强度要分开：don't need 并非决定不做，强势应对也不自动等于“完克”。检查 against / as / with 等短语究竟限定前一句的动作还是后一句的建议；ASR标点不是语音停顿的证据。两方交替指代时，避免让合并后的中文把选手淘汰、单位存活和对方应对接到同一个主体。暂时不能消歧的普通词不要靠领域黑话掩饰；名词残句、代词承接和直译比喻还需检查中文是否自然可懂。

超宽或过快时，先去掉无信息冗余；若仍超限且允许重制时间轴，优先按真实词时间拆句或在可靠停顿中调整显示。若精简会改变上述信息，保留较长忠实稿并记录排版例外。显示阈值不是删字目标。

## 语义顺序与时间轴

优先保持讲者的信息出现顺序，尤其一句对应多个显示条目时。先结果后原因的解说，不要仅为中文顺口改成原因先行后再沿用原词时间；不能提前显示尚未说出的判断。为中文语法所需的句内调整可以做，但必须核查每个时间窗的含义与实际讲话对应。

这一检查也适用于**合成一条的长字幕**：同一个 cue 并不能免除提前揭示原因、预测结果或笑点的风险。回顾引导句如“再看一下刚才发生了什么”可压缩，仍应保住引导观众回看/解释的功能，不能只留下含糊的“结果”。

合并预测与确认、动作与“漂亮”、口误与纠正、GG与赛后评价时，逐个定位后半句真正开始的词时间。若合并会提前数秒揭示结果，即使总时长、字数和CPS通过也应按可靠边界拆开；原词时间异常则先列疑点。相邻短句不能单为减少条数而合并。此处检查反应出现时刻，不要求对每个中文字符伪造音素对齐。

先判断反应向前承接还是向后引出：`I like this` 可能引出接下来的骚扰，不是赞同上一句的失误。结合左右文、实际词时间及可用画面决定归属，再决定拆合；不要只因离上一句近就并入。介绍赛事、地点或对象时，也不能把后句才说出的夺冠、失败等谓语提前补到引导句。发现此类问题后复核相邻字幕的显示顺序，不只改一个词。

拆分条件、假设及其结论时，检查逐条观看是否会暂时把假设读成断言，或把条件错接到下一项动作；不要只读拼接全文。选择保留必要的条件承接、调整真实分段或记录例外，同时避免把后出现的反应提前到条件开始。

检查句首评价、惊讶或疑问是否被后面的身份介绍、时间背景或插话挤到句尾。自然中文可以局部调整，但宜先保留“这家伙真快”“这升级便宜了”等当前判断，再交代后续范围和背景；疑问被插话打断时保留它的引导作用。若按真实词边界拆分，分别核对每条承担的含义，不能把后置原因提前后仍沿用原语序的词时间。这里不要求照搬英语句法，也不以匹配参考的断句为目标。

拆合后的 parent_ids 只证明来源可追溯。逐组比较拆合前后的**完整文本**，核对无重复、无漏掉反应/限定词，再核对每个新 cue 的语义跨度和词边界。ID 全覆盖、术语 audit 为零、短字幕消失都不等于保真通过。源文修正和显示文字精简应分开记录；不能为适应译文而改写 source 来制造一致。

用文本锚点选真实词边界时，不静默取重复短语的第一次命中。可调用 `scripts/timing_anchor.py` 的 `locate_boundary(source, asr_words, source_anchor, word_anchor=None, after_word=0, after_char=0, offset_ms=0)`；它分别验证整理后文本和原始词列表中的唯一匹配，返回候选切点，不自动拆分或审定。首个拆点应在首词之后；多次拆分传入前一边界。已记录的专名拼写修正可显式传入不同的 word_anchor；缺失词时间或歧义须先解决，不能平均分时。offset_ms 只加一次。合并相邻条目时还要查看内部停顿，避免把停顿后的独立陈述提前显示；总时长合格并不足够。

## 差异工具与实际审校

### 相邻显示窗口

S11.3 补充惊讶、喜欢某个做法、提醒与强确认的源文线索以便选入审查；只是定位线索，不自动判断中译遗漏。更新选择规则或改稿后重新生成 packet；不要拿旧包的通过记录套到新包。

游戏实况或重制字幕轴时，在校对和编辑阶段对实际保存的版本执行：

```text
python <skill>/scripts/semantic_windows.py prepare --source draft.vNN.json --field draft --output semantic-windows.vNN.json
python <skill>/scripts/semantic_windows.py check --source draft.vNN.json --packet semantic-windows.vNN.json --review semantic-decisions.vNN.json --output semantic-check.vNN.json
```

编辑后改用 target 和对应源稿重建。默认选择含英文逻辑线索、source_checks、共享/多个parent_ids或超过6.5秒的条目，并带左右邻条、原始词索引和绝对词时间；单个独有parent不代表拆合。`--all-cues` 可检查全部条目。选择条件只用于排查，不会发现所有语义错误，也不替代全片常规校对。没有词时间时明确留空；重复词保留索引，不由工具自动猜拆点。窗口中的原始ASR词可能与已证实修正的source不同，按修正记录解释，不反向覆盖源稿。

窗口核心或邻条涉及字符级拆分时，工单须另附 [字符级时间证据包](character-timing-evidence.md)。窗口中的词尾可能包含标点或继承父句范围，显示起止则可能由字符边界及延长规则计算；先核对包内索引、换算和实际公式，不能仅凭二者不同就判错轴，也不能没有依据便认定正常。校对和编辑在 note 中引用所读证据与判断，缺关键依据时记录 unclear；semantic_windows 的结构校验不替代此检查。

逐窗做两个阅读：单独播放焦点条目时是否被理解成相反结论；连同相邻条目时，主体、条件、意图、频率、动作阶段和反应是否接到正确对象。否定可能约束并列动作，不只约束最近动词；“不是有意这样称呼”也不等于“没这样说过”。再对真实词时间检查后半句是否提前出现。不能靠保留一个“不”或“如果”就认定范围正确。

审阅文件结构：`packet_digest` 是整个窗口JSON按工具 `digest()` 计算的摘要，`reviewer` 写实际执行者，`items` 每个所选cue恰好一条，含 `cue_id`、`decision`（pass/revise/unclear）、具体 `note` 和 `mappings`。每个mapping包含 `source_cue_id`、`source_quote`、`target_cue_id`、`target_quote`；引用必须在窗口内实际保存的文本中，允许跨条映射。pass/revise至少一组；unclear写明缺哪种证据，可无映射。不需要为未出现的信息填写空表。

check 检查版本、记录覆盖及引用真实性；退出码2表示仍有修订、待证据或开放源文疑点，0也不代表语义正确。它不写字幕、不会把needs_review改成reviewed。实际结论回写现有校对/编辑流程；改稿后旧packet失效。不要为让check通过而把通用说明复制到全部条目，或把它当独立模型评分。

保存精简/整形前的译稿，用脚本生成只读差异包：

```text
python <skill>/scripts/revision_audit.py --before draft-before-layout.json --before-field draft --after edited.vNN.json --after-field target --output revision-audit.vNN.json
```

旧版回归也可以比较两个含 target 的版本，但不向未见参考的新任务注入已看参考后产生的旧译。工具按 ID/共同 parent_ids 建立拆合组，不按序号 zip、不按时间猜映射。缺失映射、空译文会列 structural_errors；不应通过临时伪造 parent_ids 消除错误。两版若没有共同来源映射，应先恢复真实谱系再比较。

工具列出字数变化、文本差异、源文变化、拆合及英文中的时间/语气等词面线索。默认长度保留比例小于 0.85 时优先提醒，这是可调排查阈值，不是信息保留率；不识别中文分句倒序，也不能证明否定或数字翻译正确。返回 0 只表示比较结构可用，不表示语义已审定。仅调整显示时间且正文未变不要求再次润色，继续检查时轴与现有证据状态。

负责当前审校阶段的校对或编辑子代理阅读差异包和只读前后文，记录修改原因、需保护的源短语、具体前后译法、保留/修订/待证据结论。集中检查被精简、含限定信息、源文改变和拆合的组，其余改写仍在常规校对中检查。没有修改理由或不能证明改写更合适时保留原本准确的措辞；旧稿有错则纠正，不机械回滚。

结论写入现有 suggestions / proofreading_note / review_note，附差异包摘要或路径；示例格式是“源短语 → 所需含义；旧译 → 新译；修改原因与取舍”，不是固定通过模板。发现问题后回到新的版本稿及受影响审校批次；不可手改已冻结 SRT，也不可让差异工具自动赋予 reviewed。

采纳前，将建议文字与实际完整源句及必要前后文重新对照；不只依赖修订理由或先前摘要，防止建议自身换错主体、兵种或收入类别。编辑完成后，将每项采纳建议对应到最终保存的 target，确认实际文字已落实；只检查建议状态为 accepted 不够。改用另一措辞时核对其含义并记录取舍。字面断言只能发现未写入或写错版本，仍需看完整中文是否自然、是否指向正确实体；渲染中发现新的语义问题，应回到校对和编辑新版本再导出。
