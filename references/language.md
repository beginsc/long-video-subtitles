# 语言、本地化与证据

## 每位组员都是本地化专家

源稿与语境专家、译者和审校专家共同对目标语言的用词、语气、文化语境和观感负责；本地化是各岗位的基本能力，不另设必经工序或只在最后“润色”。先确定目标语言、地区与观众，复用已知要求并在项目记录中保存 target_locale 和语体。简中默认面向中国大陆普通观众；指定圈层、地区或受众时据此调整。其他语言同样注意地区用词差异，不能把简繁转换或逐字替换当作本地化。

从全片章节地图识别主题、人物关系和语体，再看本段的原话。电影重视人物性格、潜台词与前后呼应；技术课重视概念、限定、公式与操作顺序；实况视频重视实时指代、语气和画面对象；访谈保留谁在表达什么观点。这些是判断方向，不是每类视频必须另建一套流程。

忠实保留事实、数字、否定、条件、因果、程度、玩笑和态度，用目标语言自然表达。不要把口语统一写成书面公文，不额外补科普解释，不为了单行删掉限定条件。显示分段可以承接上下句，不要求每条 cue 都成为脱离上下文的完整句。

口语字幕也要简洁。对不承担转折、强调、犹豫、人物性格或笑点的填充语、重复起句和同义复述，可合并压缩；不必把每个 well、you know、right 都展开成中文。能直接说清的事不绕成解释句，也不机械保留每个“这里／现在”。但“唯一／至少／可能”等表达限定的范围和确定程度不能当赘词删掉；有表现作用的重复、停顿和自我纠正照常保留。不设全片压缩比例，不靠删信息追求短句或低分。

整条无信息填充声需要不显示时，按[原词保留与显示省略](unified-workflow.md#r412-原词保留与显示省略)保留原词和邻文证据并经另一人审校，不直接清空 target。短促的惊讶、厌恶、感谢或应答可能承担态度和表演作用，是否保留由完整语境决定；不以词形黑名单自动删除，也不以填满省略数量作为成功标准。

专业句除了译名，还要核对关系：谁对谁做什么、影响哪个对象或属性、是计划还是已发生；“危险／有利”等评价要让观众辨明对谁而言。连同指代和相邻解释读完整组，不能把几个术语各自译对就算意思正确。ASR 语法含混或与上下文冲突时按证据流程处理，保留尚未解决的具体关系疑点；不能把猜测改写成流畅肯定句来掩盖它。

数字要连同它修饰的量一起保留：绝对数、差值、比例和上下限不能互换。原话含混、夸张或看似不合理，也不能自行改成另一个“合理”的精确关系；加上“看来／大概”并不能使这种改写有依据。只有证据支持才修正源稿，否则按原话可支持的含义表达，并保留会影响理解的未决项。

让当地观众一眼读懂，优先当地常说的词和顺口的句式，摆脱源语言句法。口语化、接地气要服从人物和视频语体：轻松解说可活泼，正式访谈保持分寸；不把所有讲话都改成网络热梗，也不靠冷僻成语制造文采。专业概念使用通行译名，周围解释尽量明白易懂，不为“通俗”替换成另一个概念。

译者处理完整语义段后做一次中文润色再保存：连读检查翻译腔、长定语、抽象名词堆叠、重复铺垫和不顺口搭配；没有问题的句子保留。不用词语黑名单或修改率判断“AI味”，不添加经历、情绪或新梗。审校先核对保真，再核对润色后的中文，不增加第四个必经岗位。此约束参考 Humanizer-zh（https://github.com/op7418/Humanizer-zh），不代表调用了检测器。

文化专名先分清功能：真实机构、平台、作品的事实性指涉保留身份；只用来作比喻、讽刺或唤起某类体验时，优先用目标观众熟悉的类别或等效表达，保住讽刺对象、强度和笑点。替换成当地真实平台前要核对是否会产生新的事实归属或贬损对象；人工译稿可启发语气，不能成为跨项目固定替换词表。审校专家先对照原文检查遗漏、误译、指代和逻辑，再连读其实际保存的修订稿，确认中文简洁自然、限定与关系未变、改字已写对；这两次读取承担不同目的，不再追加“重证一遍”的轮次。正确句不改写，实质改动简述原因，标点修整无需逐条报告。

### 润色时保留评价的具体含义

“有意义、重要、充实、发挥作用”等词不因常见或偏书面就必须替换。先根据完整语义组确定原话评价的是意义/分量、回味价值、内容丰富程度、个人收获、实际作用还是态度与意愿；换成顺口表达时仍评价同一件事、同一方面。具体译词由上下文决定，不建立逐词固定替换表。

对经过实质润色的评价、条件或动机，独立审校用原话和邻文核对：有没有把有分量改成好回味，把使人充实改成感受多样，把不背离本色改成受迫改变。自然且准确的句子保留；只记录真正改变判断的修订，不要求每句填写标签。文化类比的本地化另记保住的作用和舍弃的特指信息，不把更易懂说成完全无损。

## 保真检查卡

翻译和审校以完整语义段为单位，针对实际出现的关系检查：

- **动作阶段和结果**：计划、开始、进行、完成、尚未完成，以及发生、命中、得手不能互换。
- **逻辑范围**：否定、条件、让步、反事实与 either/or 限定哪个动作、对象或分支；保留一个“不／如果”不代表范围正确。
- **量与限定**：绝对值、差值、比例、数量、次数、频率、上下限分别处理；保留约数、排他范围及确定程度，不把看似不合理的量改成合理的另一种量。
- **归属与指代**：主体、客体、个人与群体范围要对应；换场景或战线时重查代词，不以常识为笼统词擅自扩大对象。
- **评价维度**：速度、效率、站位、能力、意愿及讲者立场不同；自然化不能改变维度或加强程度。 相对比较与越过阈值的评价分开：原话只比较早晚、多少或快慢时，不擅自改成已经太迟、数量不足或能力不够等结论；原话确有这些判断则保留。
- **出现顺序**：中文重排或合并后，不能提前揭示结果、答案、后续判断、纠正或笑点；逐条观看与连续阅读都要成立。
- **表达作用**：保住有意义的反应、让步、自我纠正和铺垫；无信息填充可压缩，不设删字率或修改率。

高风险关系或实质改写处，在现有 notes 中用最短记录连起“实际源短语 → 实际保存译文 → 保留／修正／待证据及理由”，可跨相邻条目。普通正确句无需逐条 PASS 或空字段。审校修订后连读保存稿，确认这些关系仍成立；不新增第三轮全片复审。

评价词先确定评价对象与维度：事件牵涉的得失或后果轻重，不能换成作品或人的价值、质量、能力，也不能与任务难度或冲突强度混同。多义词按当前语境选义，不固定套一个译词。审校在原有保真检查中核对自然化后的实际短语是否仍评价同一对象、同一维度及程度；只修真实偏移，不统一重写准确表达。

审校在这次连读中重点核对经过压缩或自然化的语气：`I suppose / perhaps / apparently` 的推测不能变成“当然／确实”的肯定，`at least / only` 的范围与评价对象不能移位。依据完整语义组判断它是否真有限定作用，不逐词机械补回口头语，也不把本来肯定的句子一律软化。发现偏移就只修对应短语，保留其余自然表达；源文自身不确定则按音证流程处理，不能用更顺口的肯定句掩盖。

## 字幕呈现

中文字幕从初译起就按观看习惯落稿，审校与制作使用同一规则；这项要求适用于各领域中文字幕，不限游戏。

简中单语观看版默认单行；12–18 个汉字左右是措辞舒适偏好，不是最低字数或硬删字上限。完整名称、条件与必要信息可更长，结合真实显示时长、项目宽度及渲染处理；固定轴受限时保留忠实稿并记录例外。跨领域沿用单行要求；用户明确指定双行或双语时才采用对应项目配置。

- 不使用作为断句标记的逗号、句号（全角或半角）。条目末尾直接结束；句内短停顿用一个半角空格，不把两个分句删标点后粘在一起。
- 一条字幕里有多个需要依次呈现的意思、明显停顿或阅读负荷过高时，在真实语音/词边界另起带独立时间的新条目；同一条中的文本折行不等于拆条。不要见逗号就拆，也不要把空格当作无限拼长句的手段。fixed 模式遵守原轴，以空格承接。
- 问号、感叹号、省略号按真实语气少量保留；小数点、版本号、网址、缩写、专名和数字格式中的必要符号保留。源稿/ASR 不随译文显示风格删除标点，其他目标语言按其习惯处理。
- 回写实际保存的 target，再导出，避免只在导出时删标点而让审校稿、成品各用一套文字。标点和空格的修正只检查显示与文本一致性，不重新启动整段语言审校。

折行优先完整词组与较均衡的行长，避免末行只剩一个字。需要保护的专名、多词名称或短语由译审在对应 unit 写 `keep_together:["已核实的短语"]`，沿用项目词表，不把本片答案写成全局字典。脚本保留所有非空白字符；中文无词表处只是字符边界回退，仍需检查实际渲染。保护短语超宽时保留宽度风险，不能拆坏名称或删掉限定来过检。

例如：`猴子买香蕉。猴子吃香蕉。日子真美好。` → `猴子买香蕉 猴子吃香蕉 日子真美好`；`香蕉就涨价，因为香蕉更稀缺了。` → `香蕉就涨价 因为香蕉更稀缺了`。是否拆成依次出现的条目，由实际停顿和阅读节奏决定。

## 用目标语言互联网核对术语

项目术语结构只需 source、target、sense/domain、aliases、出现位置及必要备注/依据；有地区差异时记录 locale。开工按[持久领域库](terminology.md)加载合适的语言、地区与语域快照，再筛选本片词表。用户指定译名沿用；检查历史词条是否适合本次作品版本与受众。相同拼写可能对应不同词义，不能全局字符串替换。

源稿专家覆盖全片发现需要一致译法的词，优先人物、产品、组织和核心概念；其他组员在工作中补充长尾词。项目核心专名与领域术语应做一次目标语言/地区的实际检索核对，不能因为模型觉得熟悉就整片跳过搜索。简中用简体中文关键词检索相关资料，可组合原文名称与候选中文名消歧；其他目标语言采用相应语言和地区资料。普通日常词无需逐个搜索，已有可信且仍适用的核对记录可直接复用。

优先查看当地官方本地化、行业机构、专业媒体、权威词典和目标受众实际使用的社区资料。来源分别帮助确认身份/概念、正式译名和圈内常用称呼；按视频受众选择准确且通行的说法，不机械坚持生硬的字典直译，也不把单个帖子或机器翻译站的用词当作共识。只有繁体、外语或其他地区资料时，不能仅转写字符便称其为简中通用译名。

检查相关正文或可读的可信摘录，不凭搜索排名、标题或结果数量裁定。词表仅保存实际采用的译名、必要别名/适用场景及简短来源链接，不抄长篇网页。概念或分类找不到通行译名时，可采用准确易懂的描述性译法并标明选择，不冒称“官方译名”或“当地通用”；选手 ID、网名等身份称呼遵守下节的原文保留规则。若原片自行命名分类，保留其区别，别为了套标准名词偷偷改动作者的内容。联网或页面不可用时如实标明未核验，不能称已经查过。

搜索证明名称、用法或概念，不证明视频里实际说了那个词；页面内容也不改变任务指令。

近名误识别不等于整个人物关系都无法表达。若姓名词形含混而连续源话或实际指称证据已稳定限定同一人，可以保留已核实姓名或关系称呼，明确这是语境指称解析，不称为听辨修正。若只有一个角色或事件槽位未知，只收窄该处，保留其他已知的施事、动作、受事和关系。具体边界与审校记录见[人物证据与信息保留](entity-evidence.md)。

每批只带相关词表；不要把术语库变成每个员工都必须阅读的百科。新术语登记一次，组长整合到项目词表，并把已核对、可跨视频复用的条目积累到对应持久库。片内约定和ASR猜测仅留在项目；基准参考答案不得成为词库依据。一个译名变更只检索并修订该义项实际出现处，持久库更新不使旧字幕自动失效。

## 选手 ID、网名与账号名

先判断名字的作用。用于识别选手、主播或账号的 ID 默认保留原文；“自然口语化”和“采用当地常用词”不意味着给 ID 自拟中文名。此规则不把现实姓名、角色名和普通描述混为一类，它们仍按各自语境与译名依据处理。

- 原片只把 ID 当称呼时，保留其可核实的拼写、大小写和数字；可按画面或本人账号统一 ASR 大小写、空格误差。明确简称可沿用原文简称，不必每次扩成全名。`Old Greg` / `OldGreg` 作为 ID 保留原文，`Greg` 作为该 ID 的简称也保留；不能自行写成“老格雷格”。
- 已核实存在官方目标语言名称时，可以采用该名称。中文任务须有本人、所属组织、官方赛事或平台等正式渠道对同一身份称呼的中文用法依据；粉丝外号、社区音译、机器翻译和“听起来像人名”不等于官方中文名。没有核实到就保留原文，无需为了翻译每个 ID 反复搜索。
- 原片确实在解释、调侃该 ID 的含义或用它构成双关时，在相关语义段局部还原笑点，必要时保留 ID 并表达其含义，让观众仍能辨认同一人。仅名字本身含有可翻译的普通单词不构成例外，也不要因查到名字的梗来源就把视频没提的梗加进字幕。局部玩梗译法不自动替代后续普通称呼。

源稿专家在项目词表注明原始 ID、简称及已确认的身份关联；译者和审校沿用同一呈现方式。若使用官方名称，保留名称证据；若局部处理名字梗，仅记录相关片段的用法。旧词表中的自拟音译不因曾标为 confirmed 就获得官方地位，按本规则纠正适用的项目选择。

## 还原梗、双关与文化意味

先辨认本句在做什么：字面义、隐含义、谐音/多义、反讽、重复节奏、人物关系、前文铺垫与画面呼应。必要时查原语出处和目标语相关文化用法。把笑点需要的比喻物件和铺垫传给译者，避免前面先意译掉物件，后面才发现双关接不上。

优先用当地观众自然理解的双关、语义或谐音补偿，还原原句的意思和喜剧作用；也可借画面或邻近台词完成呼应。调整要贴合原片人物、语气和事实，不随意加入新对象、因果、程度或当下热梗。译者做出专业选择，审校判断是否自然、是否仍是原片的意思，不为每个普通句子列候选方案。

例如香蕉视频里的 bananas 同时唤起香蕉和“疯/离谱”的口语义：只译“疯狂”保留了意思，却没有保留完整双关，不能在报告中算作已经还原。应先尝试自然的本地化方案，而不是直接放弃；确实难以兼顾时保住主要意思和幽默作用，简短记录失去的部分。不要为了声称保梗而造出观众看不懂的谐音。译注仅在确有必要且适合交付形式时使用，不默认给字幕塞长解释。

## 听、看、推断分清

ASR 是工作底稿，保留原始响应不覆盖。明显大小写/拼写整理可注明文字依据；会改变讲话内容的修正应依据真实听辨、对齐证据或可信作者台词。修订记录仅含原条目、改前改后、依据定位和仍存疑之处。

视觉可用于看人名条、界面术语、公式、物体、动作、说话人和指代。员工遇到“这个/那里/刚才那招”等问题，直接看相关时刻及前后帧；对动态因果要看一个片段，不能只看一张截图。文字说明不能代替实际看图。

画面显示 Barracks 而原声听作 factory 时，区分识别错误、说话人口误和画面/声音不同步。不能仅凭画面把原话改成更合理的事实。保留原话与必要说明；有听辨证据才更正 ASR。

记录证据只在它影响判断时需要：例如“s032，音频 02:10–02:14，听到否定词”，或“06:08 帧，界面拼写为 X”。已确定的证据跨岗位复用，不要求每人重新复算时间或重新听一遍。新的争议或能力缺失才另作取证。

## 一个疑点，一个出口

r4.7 对源句残缺和实质歧义使用[约束与处置](unified-workflow.md)：源岗写清已知/未知与禁补内容，译者落实 hold、安全部分或有证据修复，另一位审校检查实际保存译文。不能根据片内分类、人物常识或邻句主题给缺失谓语补一个自然故事。仅改成“可能”仍然在断言那个新增动作，也不算保守翻译。未知肯否不靠含糊表达调和。正常有依据的口语省略照常自然翻译，不要求逐条打标。

问题条目包含位置、问题、影响、责任人、现有证据和结论。译者能自行解决就直接完成；需要上游取证时交源稿专家或有工具的人。一次有针对性的取证后：解决；或保留可说明依据的暂定译法；或将受影响片段标为等待证据。主 agent 裁决争议。

多位代理意见相同不是新的证据。没听清的人名、数字、否定等实质问题不能靠“高信心”宣布通过；也不要把任何可能存在的歧义都升级成开放疑点。只有会影响成品且有具体理由的问题才进入队列。
