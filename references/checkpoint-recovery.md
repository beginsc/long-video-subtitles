# 断点恢复

素材获取恢复先读 [media-intake.md](media-intake.md)：已 ready 的媒体校验散列后复用；下载失败保留任务目录，SnapAny 有响应时在新 attempt 重用源链接绑定的缓存，无响应的计费请求视为结果未知，不自动重提。用户下载偏好保存在技能目录之外，不随升级重置。

适用于电脑崩溃、网络中断或长任务续做。先读取项目manifest、交付选择清单、已保存job和日志，核对输入媒体、模型、术语快照与技能版本。不按文件修改时间或“文件存在”猜最新有效结果。

1. JSON须完整可解析、ID覆盖满足该阶段，源版本散列与批次一致；导出用verify-export核对，评分须与冻结SRT散列一致。失败文件保留为诊断，另存新版本恢复，不覆盖已完成基线。
2. 云端ASR/评估有job ID时先查询该任务或已完成文件，进程退出不等于任务未提交。只有查明旧任务未执行且满足后端重试规则才重提；不因本地日志没输出就重复收费请求。
3. 图片须能完整解码、采样时间和输入散列匹配才复用。音频核对PCM/切片散列和实际区间。已提取不等于已看/听，实际审阅记录只增加确实执行的范围；上下文压缩保留已审范围和下一张/下一条索引。
4. FFmpeg长片抽样按需限制解码/滤镜线程，串行推进并逐批记进度；这是资源控制，不保证解决所有死机。不启动同一输出目录的第二个渲染进程。
5. 子代理任务按 [岗位交接协议](subagent-workflow.md) 检查工单、agent_id、attempt、输入/输出摘要和 returned/accepted 状态。已返回但未合并的响应先验收，只有合并后的正式版本计入完成覆盖。旧代理状态不明时不复用其写入目录；新 attempt 只接受与当前输入匹配的一份结果。主代理是 manifest 和正式稿件的唯一写入者，员工聊天中的“完成”不能代替落盘记录。
6. 复用字符级拆分时，按 [字符级时间证据](character-timing-evidence.md) 核对包、原对齐/规则摘录及当前条目绑定，将有效证据连同已有 supplemental_inputs 纳入后续新工单。缺包时从已存原件恢复并记录真实整理时间，不补造历史审核或改写旧工单。仅新增译文/审校字段不使未变的时间依据失效；改轴、改来源或改变复核结论时另存证据并重做受影响审校。

`subtitle_workbench.save_text/save` 及调用它们的主要阶段写入现在先写同目录临时文件、flush/fsync，再以独占硬链接发布；已存在文件不会被覆盖，并发只允许一份完整结果获胜。`.pending` 文件不是完成工件，崩溃遗留项只在确认无活跃写入者且目标完整后处理。硬链接不受支持时明确失败，不退回不安全覆盖。该机制不保证多文件阶段事务或断电后的整个文件系统持久性；其他外部工具仍可能留下半文件，所以恢复验证仍需执行。
